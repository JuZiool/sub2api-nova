# Sub2API Nova 前端液态玻璃改造执行方案

## 1. 方案结论

Nova 前端继续使用 Vue 3、TypeScript、Vite 和 Tailwind CSS，不迁移到 React 或 Next.js。

改造采用以下组合：

- 普通毛玻璃作为整体视觉基础
- 液态玻璃只用于导航、菜单、切换控件和少量重点操作
- 表格、日志、长表单保持高对比度实色或轻透明表面
- Chromium 浏览器显示完整折射效果
- Safari、Firefox 和低性能设备自动降级为普通毛玻璃
- 保留现有路由、接口、权限、国际化和业务功能

当前项目已经存在 `.glass`、`.glass-card`、`.card-glass`、青绿色主色、深色模式和布局组件，本次工作是在现有设计基础上统一和增强，不重新搭建前端架构。

## 2. 改造目标

1. 建立统一、克制、适合高频操作的 Nova 视觉系统。
2. 提升导航、数据概览、弹窗和关键操作的质感。
3. 保证账号、分组、用户、日志、计费等高密度页面的可读性。
4. 保证浅色模式、深色模式、桌面端和平板/移动端体验一致。
5. 不改变现有业务行为，不因视觉效果影响请求、表格和表单性能。
6. 建立可复用组件，避免每个页面单独编写玻璃样式。

## 3. 不在本次范围内

- 不重写后端接口。
- 不调整数据库结构。
- 不迁移 React、Next.js 或其他前端框架。
- 不一次性引入多个完整 UI 组件库。
- 不在所有卡片、表格单元格上使用液态折射。
- 不重做与视觉改造无关的业务流程。

## 4. 设计方向

### 4.1 产品定位

Nova 是高频使用的 AI API 网关和运营后台，界面应安静、专业、紧凑，优先支持扫描、比较和重复操作。液态玻璃用于建立品牌辨识度，不承担主要内容展示。

### 4.2 色彩

继续使用现有 Teal/Cyan 青绿色作为品牌主色，搭配中性灰、深色背景和独立的状态色，避免界面被单一色系占满。

- 品牌主色：Teal，用于选中状态、主操作、焦点和关键指标
- 信息色：Blue，用于普通信息和链接
- 成功色：Emerald
- 警告色：Amber
- 危险色：Red
- 中性色：Gray/Slate，用于背景、边框和正文层级

所有颜色通过 Tailwind 配置或 CSS 变量管理，页面组件中不新增零散的原始颜色值。

### 4.3 圆角与密度

- 页面容器和普通卡片：最大 8px 圆角
- 输入框、菜单和工具栏：6px 至 8px
- 状态标签、头像和明确的胶囊控件可以使用全圆角
- 桌面表格行高建议 44px 至 48px
- 顶部栏高度建议 56px 至 60px
- 正文默认 14px，紧凑辅助信息最低 12px
- 字间距保持 `0`，不使用随视口缩放的字体

### 4.4 玻璃层级

建立三种明确层级，禁止随意叠加：

| 层级 | 用途 | 实现 |
| --- | --- | --- |
| `surface-solid` | 表格、日志、长表单 | 高对比实色或接近实色背景 |
| `surface-glass` | 顶栏、侧栏、弹窗、概览面板 | 半透明背景、10px 至 20px 模糊、细边框 |
| `surface-liquid` | 悬浮操作、模式切换、用户菜单等重点控件 | 折射、边缘高光、轻微色散和弹性反馈 |

同一视口内建议最多存在 3 至 5 个活跃液态玻璃元素，避免 GPU 持续高负载。

## 5. 技术方案

### 5.1 基础样式

优先使用现有 Tailwind CSS 和 `frontend/src/style.css` 实现普通毛玻璃、颜色变量、边框、阴影和降级样式。

计划新增统一样式令牌：

- `--nova-bg`
- `--nova-surface`
- `--nova-surface-glass`
- `--nova-border`
- `--nova-highlight`
- `--nova-shadow`
- `--nova-blur`
- `--nova-motion-fast`
- `--nova-motion-normal`

### 5.2 液态玻璃候选库

首选验证 [`@wxperia/liquid-glass-vue`](https://github.com/WXperia/liquid-glass-vue)：

- Vue 3 和 TypeScript 原生组件
- 支持折射、模糊、色散、弹性和鼠标交互
- 可封装到现有页面，不需要更换框架
- Safari 和 Firefox 仅支持部分效果，必须准备 CSS 降级

备选验证 [`liquid-gl`](https://github.com/naughtyduk/liquidGL)：

- 框架无关的 WebGL 实现
- 折射效果更明显
- 更适合固定定位的顶部栏、悬浮工具栏等少量区域
- 页面快照和动态内容处理成本更高

正式采用前先制作独立效果样板。若候选库影响滚动、文字清晰度、内存或 GPU 占用，则不引入依赖，改用 SVG 滤镜加 CSS 的轻量实现。

### 5.3 组件封装

计划新增以下基础组件：

```text
frontend/src/components/ui/NovaSurface.vue
frontend/src/components/ui/NovaLiquidGlass.vue
frontend/src/components/ui/NovaIconButton.vue
frontend/src/components/ui/NovaSegmentedControl.vue
```

- `NovaSurface`：统一实色、毛玻璃和浮层三种表面
- `NovaLiquidGlass`：隔离第三方库，集中处理浏览器降级和性能开关
- `NovaIconButton`：统一图标按钮尺寸、提示和焦点状态
- `NovaSegmentedControl`：用于主题、视图和模式切换

业务页面不直接调用第三方液态玻璃库，避免后续更换实现时批量修改页面。

### 5.4 浏览器降级

降级顺序：

1. 支持完整效果时启用液态折射。
2. 不支持位移滤镜或 WebGL 时使用 `backdrop-filter` 毛玻璃。
3. 不支持 `backdrop-filter` 时使用高透明度实色背景。
4. 开启 `prefers-reduced-motion` 时关闭弹性、跟随和持续动画。

液态玻璃失败不得造成内容不可见、按钮无法点击或布局尺寸变化。

## 6. 分阶段执行

### 阶段 0：建立基线

工作内容：

- 记录当前依赖、主题、路由和核心页面结构
- 保存管理员和用户端关键页面截图
- 记录桌面端与移动端主要交互流程
- 运行现有类型检查、测试和构建，确认改造前基线

重点页面：

- 登录页
- 管理员仪表盘
- 账号管理
- 分组管理
- 用户管理
- 使用日志
- 用户仪表盘
- API Key 页面
- 系统设置

验收标准：基线检查通过，已记录现有失败项，后续能区分历史问题和本次回归。

建议提交：`测试：建立前端视觉改造基线`

### 阶段 1：设计令牌和基础表面

修改范围：

```text
frontend/tailwind.config.js
frontend/src/style.css
frontend/src/components/ui/
```

工作内容：

- 统一背景、表面、边框、阴影、圆角和动效时长
- 重构现有 `.glass`、`.glass-card` 和 `.card-glass`
- 增加三层表面组件和降级样式
- 保留现有类名兼容层，避免一次性破坏旧页面
- 增加 `prefers-reduced-motion` 和 `@supports` 规则

验收标准：深浅主题均清晰，旧页面未出现布局变化，普通毛玻璃无需 JavaScript 即可工作。

建议提交：`样式：建立 Nova 玻璃视觉基础`

### 阶段 2：液态玻璃技术验证

工作内容：

- 制作独立的组件展示页或开发环境样板
- 对比 Vue 组件、WebGL 和 SVG/CSS 三种实现
- 验证按钮、菜单、长文本、滚动背景和动态数据
- 检查 Chrome、Edge、Firefox 和 Safari 降级表现
- 测试 1、3、5、10 个液态元素的帧率和 GPU 占用
- 确定最终实现并封装到 `NovaLiquidGlass`

通过条件：

- 不阻塞点击和键盘焦点
- 滚动时没有明显闪烁或错位
- 同屏 5 个元素时交互保持流畅
- 关闭效果后布局尺寸不变化
- Firefox 和 Safari 能正常显示毛玻璃降级版本

建议提交：`功能：增加可降级的液态玻璃组件`

### 阶段 3：改造全局框架

修改范围：

```text
frontend/src/components/layout/AppLayout.vue
frontend/src/components/layout/AppHeader.vue
frontend/src/components/layout/AppSidebar.vue
frontend/src/components/layout/AuthLayout.vue
frontend/src/components/layout/TablePageLayout.vue
```

工作内容：

- 调整页面背景和内容层级
- 顶部栏和侧边栏使用普通毛玻璃
- 用户菜单、主题切换和少量悬浮控件使用液态玻璃
- 统一导航激活、悬停、键盘焦点和折叠状态
- 移动端侧栏改为清晰的抽屉层，不与正文重叠
- 移除只用于装饰且影响阅读的背景元素

验收标准：导航路径、主题切换、语言切换、权限菜单和移动端抽屉功能保持不变。

建议提交：`样式：重做 Nova 全局导航与布局`

### 阶段 4：改造仪表盘

修改范围：

```text
frontend/src/views/admin/DashboardView.vue
frontend/src/views/user/DashboardView.vue
```

工作内容：

- 重新组织核心指标、趋势、快捷操作和系统状态
- 指标面板使用普通毛玻璃，不使用强折射
- 快捷操作和筛选切换可局部使用液态玻璃
- 图表保持稳定尺寸，避免加载时引发布局偏移
- 状态不能只依赖颜色，必须同时使用文本或图标

验收标准：数据与现有接口一致，图表、统计、刷新和跳转功能无回归。

建议提交：`样式：重做管理员与用户仪表盘`

### 阶段 5：改造数据管理页面

建议按业务组分批处理，避免单次修改范围过大：

1. 账号、渠道、代理和分组
2. 用户、订阅、兑换码和推广码
3. 使用记录、审计日志、风控和监控
4. 系统设置、公告和备份

工作内容：

- 统一页面标题、筛选工具栏、表格、分页和批量操作
- 表格主体使用 `surface-solid`
- 筛选栏和批量操作栏使用轻量毛玻璃
- 图标按钮提供 tooltip 和 `aria-label`
- 移动端宽表使用横向滚动或信息卡片视图
- 加载、空状态、错误和成功反馈保持完整

验收标准：所有搜索、筛选、排序、分页、选择、编辑、删除和批量操作均可用。

建议提交按页面组拆分，例如：`样式：统一账号与渠道管理页面`

### 阶段 6：改造认证和用户流程

修改范围：

```text
frontend/src/views/auth/
frontend/src/views/setup/
frontend/src/views/user/
```

工作内容：

- 统一登录、注册、找回密码和首次初始化页面
- 表单使用高对比背景，避免输入区域被折射
- 明确字段标签、错误位置、加载和提交结果
- 支付、二维码和外部回调页面保持原有安全流程
- API Key、用量和个人资料页面沿用统一数据页面规范

验收标准：认证、验证码、OAuth、支付和初始化流程不因样式调整改变行为。

建议提交：`样式：统一认证与用户中心页面`

### 阶段 7：响应式、无障碍和性能收尾

检查视口：

- 390 x 844
- 768 x 1024
- 1280 x 800
- 1440 x 900
- 1920 x 1080

检查内容：

- 无页面级横向溢出
- 文字、按钮和标签不重叠
- 键盘可访问全部交互控件
- 焦点样式清晰可见
- 正文对比度至少达到 4.5:1
- 触控目标尽量不小于 44 x 44px
- 动画主要使用 `transform` 和 `opacity`
- 无障碍模式下关闭非必要动态效果
- 大型弹窗和非首屏组件按需加载
- 表格和日志继续使用现有虚拟化能力

建议提交：`优化：完善前端响应式与无障碍体验`

## 7. 验证命令

每个阶段至少执行：

```bash
cd frontend
pnpm typecheck
pnpm lint:check
pnpm test:run
pnpm build
```

提交前执行：

```bash
git diff --check
```

涉及页面视觉变化时，需要保存桌面端和移动端截图，对比以下内容：

- 页面是否完整显示
- 文本是否溢出或遮挡
- 弹窗、菜单和抽屉层级是否正确
- 深浅主题是否存在低对比文字
- 液态玻璃失效时是否正确降级

## 8. 完成标准

满足以下条件才算完成：

- 原有前端业务功能全部保留
- 全局布局和核心页面使用统一设计令牌
- 液态玻璃仅在约定区域使用
- 不支持完整效果的浏览器可以正常操作
- 深浅主题和五种目标视口通过视觉检查
- 类型检查、Lint、测试和生产构建通过
- 没有提交 `.env`、截图缓存、构建产物或运行数据
- 每组独立修改均使用中文 Git commit 记录

## 9. 推荐执行顺序

先完成阶段 0 至阶段 3，形成可运行的全局框架样板；确认视觉方向后，再批量改造仪表盘和业务页面。不要在设计令牌和液态玻璃降级方案确定前同时修改所有页面。
