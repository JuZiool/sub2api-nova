## 2. 关键发现

### 2.1 Nova 真实定制面(经逐字审计)
- ✅ **真定制**:Codex 额度透支体系(上游零相关文件)、分组模型倍率与定价审计、单机多窗口指纹收敛、品牌前端、部署与同步运维体系。
- ❌ **假定制(实为上游功能,Nova 仅继承/落后)**:国产供应商(kimi/zhipu/deepseek,上游 Randark 2026-08-15 引入)、分时定价(上游 erio/lyen1688)、支付目录、`user_platform_quota`。
- ⚠️ **搬运而非自研**:14 个"看似 Nova"的提交实为上游修复的中文标题搬运(代码逐字一致),如 WebSocket 隔离、HTTP bridge、keepalive、工具输出保留等。

### 2.2 融合机制缺陷(已修复)
- **上游新增迁移被保护清单静默过滤**:上游提交同一批次含代码与迁移时,迁移文件(保护路径)被丢弃、代码被吸收,导致新装库缺 `fast_multiplier` 等列(历史事故)。
- **保护清单误保护上游功能**:国产供应商/支付等被当作 Nova 定制锁住,造成 Nova 落后于上游重构(如 `QueryUsageForAccount` 公共 API)。

### 2.3 计费问题(8 项决策)
- 乘 0 免费漏洞(目录单侧漏配倍率时对应分项计 0);
- gpt-5.5/5.5-pro 兜底价错误别名为 gpt-5.4(潜在收入损失 2x);
- DeepSeek 兜底价停留在旧官方价;
- 其余口径项经核实为等价(Nova 通用 2x = 上游显式 2x)或有意为之(冻结)。

## 5. 当前系统状态

```
上游每天 08:00(北京)自动检查
 → 有新提交 → 自动生成同步候选 PR(sync_upstream.py:
    迁移自动吸收 / 假保护自动跟随 / 冲突阻断)
 → PR 验证全绿 → 自动合并
 → 自动构建 GHCR 镜像(sha 标签 + latest)
 → 构建成功才推进上游成功基线
 → 冲突或测试失败 → 暂停并等待人工
```

服务器升级方式:`deploy/update.sh` 或 `install.sh` 输入 3(拉取最新 GHCR 镜像)。
